# Divisão de tarefas (6 pessoas) — entrega: semana que vem

| Pessoa | Responsabilidade | Entregável |
|---|---|---|
| 1 | Criar repo GitHub, subir projeto base, convidar todos, revisar PRs | Repo funcionando (quarta) |
| 2 | Tela do solicitante: validações, melhorias de layout (`solicitante.hbs/.js`) | PR + commits |
| 3 | Tela do prestador: filtros, melhorias de layout (`prestador.hbs/.js`) | PR + commits |
| 4 | Service e dados: evoluir `servicos.js` (ex.: avaliação, categorias) e testes | PR + commits |
| 5 | README final: conferir versões, testar instalação do zero em máquina limpa, prints | README revisado |
| 6 | Apresentação: slides (PowerPoint/PDF) seguindo ROTEIRO, e roteiro da demo | Slides |

**Todos:** escrever o próprio relatório individual (modelo abaixo) e participar do ensaio na segunda.

## Modelo de relatório individual
1. Nome, função no grupo
2. Tarefas que realizei (arquivos, componentes, rotas, commits/PRs)
3. Como funciona o que desenvolvi (com prints)
4. Dificuldades e como resolvi
5. O que aprendi sobre Ember.js
6. Referências usadas (incluindo ferramentas de IA, se a disciplina exigir declarar)

## Roteiro da apresentação (10–12 min)
1. Problema e proposta · 2. Ember.js e por que escolhemos · 3. Arquitetura (router, controllers, service) · 4. Demo: solicitante publica → prestador aceita → conclui · 5. Desafios e aprendizados · 6. Próximos passos
